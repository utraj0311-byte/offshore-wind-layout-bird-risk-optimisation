## Which scripts are the scientific executable?

`metrics/metric_4a/metric4a_preflight/metric4a_run72.py` is the final 72-sector run controller and imports unmodified `model8_code/model8_meso_response.py`, `model8_aep_problem.py`, `model8_batching.py` and `run_model8_multiobjective.py`. Historical direct 12-sector runner is preserved in `model8_code/run_model8_multiobjective.py` **but not the thesis-authoritative 72-sector executable**. The 72-sector code inserts the preflight directory and sibling `model8_code` in Python's module search path and expects the original files under the same relative paths.

**Do not execute the `run`/`resume` modes of `metric4a_run72.py` simply to review archived results:** those modes launch or resume optimisation. The `verify` mode also constructs reference scenarios/FLORIS AEP and requires earlier generated preflight reports; it **cannot pass from this GitHub-only archive in its present state** because `preflight_reports/` is missing. The post-run `endpoints` mode computes FLORIS AEP (including 1° checks); no such computation was made for packaging. The independent confirmation `verify` additionally requires generated `<scratch>/metric_4a_72sectors_postrun/endpoint_aep_1deg.json` and `geometry_report.json`. Missing reports must not be invented.

A successful reproduction therefore needs the recorded environment (Windows/Python 3.11.15, FLORIS 4.6.5, pymoo 0.6.1.5, NumPy 2.4.6, SciPy 1.17.1), plus generation/collection of original preflight reports according to the unchanged original preflight script before trying its run controller. Never treat archived final numeric outputs as being regenerated by this package.
